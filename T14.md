## T14 — Remote single-owner access through Cloudflare (#1376)

### 1. Decision

Choose **Cloudflare Tunnel → Cloudflare Access with Managed OAuth → the separate, loopback-bound `eliot-dream-gateway`**, not a Worker and not a tunnel to the ordinary agent bridge: this is an **OWNER DEFAULT (proposed)** transport selection implementing the already documented bounded gateway without building an ELIOT authorization server (`docs/architecture/I07-05-named-pipes.md:16-26@7a2b5fd4`; `docs/architecture/I09-13-remote-dreamer-gateway.md:3-28@7a2b5fd4`; [V1], [V5], [V6]).
The owner's PC keeps its existing local stdio/IPC path; an explicitly enabled remote machine client uses a dedicated Cloudflare Service Auth token, whereas ChatGPT uses Cloudflare-managed OAuth, never the local bridge credential (`docs/architecture/I07-05-named-pipes.md:11-26@7a2b5fd4`; [V1], [V2]).
Expose **read-only bounded question/recall only**, with **`search` and `fetch` as proposed remote compatibility aliases** over existing query/read semantics, because this supports ChatGPT's citation interface without exposing the normal eight-tool control surface (`docs/architecture/A09-06-remote-dreamer.md:3-13@7a2b5fd4`; `docs/architecture/I07-06-mcp-surface.md:16-51@7a2b5fd4`; [V8]).
Cloudflare performs external authentication; the origin validates its signed assertion and maps only the configured owner identity or designated owner service token to **one Kernel-issued owner principal with a restricted remote-read profile**, not administrative authority or ELIOT accounts (`docs/architecture/I15-02-principal-and-session-binding.md:3-16@7a2b5fd4`; `docs/architecture/I15-13-remote-dreamer-security.md:4-12@7a2b5fd4`; [V3], [V4]; [O1]).
Keep WorkScope selection, query meaning, canonical reads and visibility decisions with their existing Governor owners, and keep operational Session/fence authority with Kernel; neither an MCP session ID nor a Cloudflare header becomes an ELIOT grant (`crates/governor/eliot-read/src/lib.rs:1-8@7a2b5fd4`; `docs/architecture/I07-07-mcp-versions-and-stateless-core.md:3-9@7a2b5fd4`).
Keep memory writes, agent launches, local tools, database access, raw telemetry and Kernel/ELIOT administration local-only; Cloudflare administration here means management of remote exposure and access policy, not an additional remote Kernel control API (`docs/architecture/I09-13-remote-dreamer-gateway.md:18-28@7a2b5fd4`; [O1]).
ELIOT does not read Google Drive for this feature: the owner's ChatGPT Google Drive connection remains a separate authorization boundary, with no Google token or Drive synchronization added to ELIOT (`docs/architecture/A09-06-remote-dreamer.md:3-13@7a2b5fd4`; [O1], [V10]).
Adopt the replacement contract text before implementing the post-install slices below, and do not call the feature complete until ChatGPT consumes a real ELIOT result with usable citations (`docs/architecture/A00-06-changing-the-architecture.md:3-16@7a2b5fd4`; `docs/architecture/I00-10-user-outcome-recovery-invariants-and-anti-proxy-development-contract.md:59-75@7a2b5fd4`; [O1]).

### 3. Current code reality

**Local transport is not an HTTP server.** `TransportProfile` describes stdio or loopback validation; it does not listen on a socket (`crates/surfaces/eliot-mcp/src/core.rs:22-40@7a2b5fd4`). ### 5. Slice plan

#### Implementation contract and proposed defaults

Everything marked **OWNER DEFAULT (proposed)** below needs explicit acceptance in the owning work item before code relies on it. These choices refine the cited bounds; none is claimed to exist at the pin.

**Connection.** Use one owner-controlled hostname and one Access application, with owner-only user access and, when needed, one specifically selected Service Auth token. No `Everyone`, domain-wide membership shortcut, Bypass policy or public fallback. Configure Managed OAuth with DCR and copy the **exact** callback from ChatGPT; verify resource discovery, S256 and issuer behavior against [V9]. A generic Access browser redirect alone is insufficient. Cloudflare implements OAuth endpoints; ELIOT implements no login page, token endpoint, refresh-token store or account database. **OWNER DEFAULT (proposed):** no Worker or MCP portal, because the documented managed authorization path avoids another hop and secret-bearing component. [V1], [V7], [V9].

The gateway's HTTP listener is distinct from the ordinary loopback MCP profile. Bind only an explicitly configured loopback address/port; validate the exact public Host and any present Origin against a narrow configured allowlist. Do not relax the existing local `LoopbackProfile` Host/credential rules to make the tunnel work. Reject unsupported methods/routes and oversized input before semantic dispatch. Streamable HTTP is the selected external transport; keep protocol negotiation and compatibility inside the adapter, never inside Session semantics. (`docs/architecture/I07-05-named-pipes.md:26@7a2b5fd4`; `docs/architecture/I07-07-mcp-versions-and-stateless-core.md:3-9@7a2b5fd4`.)

**Identity.** Validate `Cf-Access-Jwt-Assertion` on every gateway request: signature/allowed algorithm, exact issuer and audience, expiry and applicable not-before constraints. Obtain keys only from the configured team's trusted endpoint; bounded key refresh failure denies unverifiable requests. Neither raw email headers nor a decoded-but-unverified JWT qualifies. User mapping matches `(issuer, user, sub)` exactly; machine mapping matches `(issuer, service, common_name)` exactly and cannot treat empty `sub` as a user. Do not JWT-decode the opaque OAuth bearer or forward it to Kernel. [V1]–[V4].

**OWNER DEFAULT (proposed):** the approved installation descriptor binds these external aliases to one existing owner principal and one restricted remote-read profile, because multiple credentials for one owner do not require multiple ELIOT accounts. Kernel issues/revalidates its operational binding through the authenticated local gateway process and retains the current nonce/SID/epoch checks. The descriptor, not request JSON, grants the profile. Cloudflare identity is external admission evidence/audit correlation, not a constructor for `Principal`, `Session`, `WorkScope` or capabilities. A gateway must not masquerade as an ordinary full-authority agent bridge. Existing local admission secrets remain exclusively on the Windows IPC leg. (`docs/architecture/I15-02-principal-and-session-binding.md:3-16@7a2b5fd4`; `crates/kernel/eliot-kernel-service/src/host_request_binding.rs:70-190@7a2b5fd4`.)

**Surface.** Publish only `search(query)` and `fetch(id)` on `/mcp`; no `eliot.observe`, `eliot.act`, `eliot.coordinate`, `eliot.finish`, full catalogue, arbitrary `resources/read`, resource enumeration or control routes. `search` asks for relevant *released answer items within one bounded read bundle*. It is not raw database search. **OWNER DEFAULT (proposed):** one explicitly selected WorkScope and a locally compiled context-reconstruction QueryIntent tied to the bundle's exact snapshot; this avoids guessing task/scope or silently treating historical memory as current truth. Unsupported intent or stale coverage gets the owner's typed disposition, not a fabricated empty result. The read owner selects/adjudicates content; the MCP adapter merely translates it. (`docs/architecture/I07-06-mcp-surface.md:16@7a2b5fd4`; `docs/architecture/I15-13-remote-dreamer-security.md:7-10@7a2b5fd4`.)

`fetch` expands only a previously issued answer item. Return the **complete bounded, redacted item**, not a silently truncated source represented as complete. Preserve source revision, freshness, assurance, limitations and citations within the released text. The gateway's `https://<configured-host>/answers/<opaque-ref>` URL resolves that same immutable item after authentication and current visibility checks; it never redirects to a local handle. Construct URLs from trusted configuration, not client Host/query text. Use generated `search` results `{results:[{id,title,url}]}` and `fetch` results `{id,title,text,url}`; produce matching structured content and JSON text. [V8]; `docs/architecture/I09-13-remote-dreamer-gateway.md:26-28@7a2b5fd4`.

References must be gateway-scoped, signed, expiring and bound to principal/read profile, scope, revision and current authority. Use audited cryptographic primitives for integrity, not a bespoke authentication protocol. An opaque lookup key plus integrity tag must not encode recoverable DB keys, filesystem paths, `eliot://` URIs or internal capabilities. The bounded cache contains released projections, not canonical memory or an alternative retrieval database. Authentication, policy narrowing, erasure and fence checks apply again on expansion. All external requests remain instruction-tainted; a valid Access assertion is not content assurance. (`docs/architecture/I09-13-remote-dreamer-gateway.md:8-28@7a2b5fd4`; `docs/architecture/I15-01-threat-model.md:6-15@7a2b5fd4`.)

**OWNER DEFAULT (proposed):** initially admit 30 tool calls/minute per owner across both credential classes, burst 5, at most 2 in flight, a 30-second total deadline, 32 KiB encoded input, 8 KiB query text, 64 KiB encoded tool output, at most 5 returned items, and a 64-item/4 MiB volatile answer cache. Reference lifetime is at most five minutes and never exceeds the applicable grant/Session lifetime. These are small development bounds, not vendor quotas; apply any tighter existing Governor budget. Count the whole encoded MCP envelope, including duplicated compatibility content. Use 429 plus a bounded retry indication for admission limits, and a typed resource/deadline error rather than partial success. No new token-billing or distributed limiter system is needed. (`docs/architecture/I15-13-remote-dreamer-security.md:6-10@7a2b5fd4`.)

**Operations.** Gateway and tunnel are independently removable. Disable ingress, invalidate the remote Kernel binding and outstanding answer resources, then stop the gateway as necessary; ordinary local ELIOT remains available. Rotate/revoke the actual Cloudflare service token when relevant. Do not claim immediate remote revocation from offline JWT validation alone. Avoid caching authenticated content at the CDN; return private/no-store responses and log neither credentials nor request/answer bodies. Security events go through the existing Watchdog path without raw telemetry exposure. Google Drive stays entirely outside this implementation. (`docs/architecture/I15-04-secrets.md:8-12@7a2b5fd4`; `docs/architecture/I15-13-remote-dreamer-security.md:10-12@7a2b5fd4`; [O2], [V2], [V10].)

### 6. Risks

**Vendor interoperability is documented, not demonstrated here.** Managed OAuth is Beta, and account entitlements, PKCE/discovery metadata, the selected callback and negotiated MCP version can differ from assumptions. S0 checks actual configuration availability early; S4 proves the real ChatGPT OAuth exchange. Do not advertise production support, pick an unverified SDK patch, add custom OAuth, or weaken authentication to make a demo pass. [V1], [V7], [V9].

**Admission is not answer delivery.** The pinned production path's `Accepted`/`ResultReceived` behavior can conceal a missing consumer edge. S1's fresh local query must return the actual payload through the real binder before gateway work counts as progress; discovery-only success cannot substitute for that result. Newer main may already have repaired this path, so rebase the implementation plan to its actual owner rather than copy old code.

**Authentication is not authorization or truth.** The wrong service-token identity mapping, full local bridge grants, trusted forwarded headers, unsigned references, leaked resource URLs or instruction-following on fetched content would defeat the boundary. S3 tests origin denial and constrained expansion; S5 tests actual visibility/fence invalidation. Even the owner must receive no remote write/launch authority under this decision.

**Resource safety and citations can conflict if implemented carelessly.** URL-less responses are not native citations, while public URLs or silent full-source expansion would leak data. S2/S3 use authenticated gateway answer resources; S5 proves owner-readable citations and stranger denial without substituting local paths or sharing links publicly. Already disclosed ChatGPT content cannot be recalled by later gateway revocation; only future access can be blocked.

**Ownership/adoption drift can invalidate placements.** Proposed leaf paths are implementation placements under existing owners, not invented authority. S0 checks the actual normative adoption mechanism, and each writer reruns scoped reading before changes. No generated hash, router receipt, compile result or live proof is supplied by this brief. Keep operational evidence local or on the owning issue; the committed artifact is only this bounded handoff.
