# Программа, ревизия v1.4

Продолжение `W1-RESULT-ENVELOPE-PROGRAM-REVISION-v1.3.md`. Исправляет четыре
дефекта программы, вскрытых исполнением W0/W1, и выдаёт три задания на закрытие
гейта W0. Программная авторитетность: не Architecture, не Implementation, не
Product Proof, не cutover.

Действующая копия программы — `docs/tasks/RECOVERY_PROGRAM_v1.md`.
`docs/architecture/RECOVERY_PROGRAM_v1.md` — копия v1.1, отменена, удалить:
читающий её агент получает отменённые правила конверта результата.

## Исправления программы

### 1. Linux исключается из DoD W0

`W0-05` требует один профиль шагов через одного владельца и про Linux не
говорит — требование появилось только в строке DoD. Продукт Windows-only: 53
исходника под `cfg(windows)`, все три workflow `runs-on: windows-latest`,
`ci.yml` фиксирует *no OS matrix*, порта нет ни в одной волне W0–W7.
`scripts/verify.sh` делегирует в `verify.ps1` через одного владельца — пункт
закрыт по существу.

```
DoD W0:  scripts/verify.{sh,ps1} → один профиль шагов через одного владельца
Гейт:    PROFILE_PARITY_NATIVE_LINUX_BUILD_BLOCKED → RESOLVED_BY_PROGRAM_REVISION
```

Нативный Linux-тулчейн не ставится, Linux-receipt не заявляется.

### 2. W1 закрывается по уже установленному

Каждое ревью W1-01/02/05/06 объявляет перепись *stable and reusable* и
отклоняет только конверт. Дальнейшие итерации знания о продукте не добавляют.

Артефакт W1 принимается как `EVIDENCE_ONLY` при четырёх условиях:

1. генерируется одной командой;
2. входное множество связано content digest, включая всех свидетелей;
3. верификатор пересчитывает артефакт и отвергает add/remove/tamper по каждому
   семейству полей;
4. статически неустановленное помечено `UNKNOWN`, а не выведено.

Замечания к форме конверта и к выбору семантического против байтового сравнения
там, где верификатор уже пересчитывает артефакт — `NOTED_NON_BLOCKING`.

Текущие попытки последние. Каждая получает disposition в одну итерацию:
`INTEGRATED_EVIDENCE_ONLY` либо `PRESERVED_DONOR` с перечнем отсутствующего.
Mechanism Review по этим пунктам не открывается.

### 3. Посылки A2 и A3 заменяются переписью

`W1-06` опроверг обе, и это штатный исход по DoD W1.

Программа исходила из «132 E2E выключены = контур обратной связи выключен
целиком». Перепись: **331 кандидат, 82 выключено, 249 включено**. A3
(«подписываемый набор не содержит исполняемого продукта») — ложна. A1
сохраняется только для узкого прямого Cargo-предиката.

Следствие: **W5 переформулируется** с «вернуть E2E» на «включить 82
выключенных, каждый как Edge proof своего cell». DoD W5 сохраняется: 0 тестов,
выключенных без причины и владельца.

Этой заменой пересмотр программы по итогам W1-06 исполнен. W2 более не
блокируется несделанным пересмотром — только гейтом W0 и dispositions W1.

### 4. Запрет на коммит снимается в границах W0

Гейт W0 не может закрыться при незакоммиченном дереве: hosted-прогон падает на
шаге `normative`, потому что `docs/ARCHITECTURE_CONTRACT.md` отсутствует в
дереве. Локальные PASS красный receipt не заменяют.

Коммит группами по владельцу; перед push — локально зелёный
`scripts/verify.ps1`. В дерево обязаны попасть, как минимум:

```
docs/ARCHITECTURE_CONTRACT.md   docs/UNIMPLEMENTED.md   docs/conformance.toml
scripts/gen-*.ps1               scripts/verify-*.ps1
bins/eliot/src/bootstrap_draft.rs   bins/eliot/tests/bootstrap_brief.rs
swarm/**
```

Прочие исключения v1.3 в силе: контракт `eliot-swarm` не мутируется,
`TerminalWorkUpdate`/`attempt_id` не выдумываются, activation и cutover не
выполняются, реальный `C:\ProgramData\Eliot` юнит-тестами не мутируется.

## Задания

| ID | Содержание | Proof |
|---|---|---|
| `W0-07` | `bins/eliot-watchdog/Cargo.toml:21` — перенести `eliot-platform-windows = { features = ["test-support"] }` из `[dependencies]` в `[dev-dependencies]`; образец `bins/eliot/Cargo.toml:49` | `cargo tree -p eliot-watchdog -e normal` без фичи; focused clippy `-D warnings` и тесты watchdog зелёные |
| `W0-08` | Очистить `C:\ProgramData\Eliot`, затем один quiescent full-profile прогон | Агрегатный receipt. Исполнение авторизации `W0-WATCHDOG-FIXTURE-RETRY`, новой не требуется |
| `W0-09` | Коммит и push по §4 | Зелёный hosted receipt на `main` |
| `W0-10` | Связать нормативный якорь `I:209` с кодом: `BootstrapBriefCompiler` и `CurrentSystemEvidenceCompiler` дают 0 вхождений в workspace | Поиск по нормативному имени приводит к реализации; либо запись Recoverable Deviation по `A0.6` |

**W0-07.** Гейт `#[cfg(any(test, feature = "test-support"))]` стоит корректно на
thread-local, сеттере, ридере и на ветке в `expected_root()`. Но watchdog
включает фичу обычной зависимостью, поэтому поставляемый `eliot-watchdog.exe`
компилирует `override_protected_root` и ветку подмены защищённого корня.
Докстринг модуля утверждает *«Production builds do not contain this surface»* —
для watchdog это неверно, и это компонент, стерегущий ровно эту границу. Не
удалённая дыра: требуется код внутри процесса. Правка в одну строку.

**W0-08.** В каталоге 69 файлов, 61 КБ, ноль бинарников: скелеты каталогов и
маркеры `.eliot-install-*.receipt`, включая фикстурный ключ `0123456789abcdef…`
и ключ `4b6c489…` от одноимённого коммита. Установки за ними нет — это осадок
прогонов. Чистка даёт авторизованному прогону чистый baseline.

**W0-10.** Норматив `I:209` предписывает `BootstrapBriefCompiler` в крейте
`eliot-bootstrap`, работающий против нормативной пары, типизированного seed,
Bootstrap Rule Catalogue и `CurrentSystemEvidenceSnapshot`. Возможность
реализована и admitted, но под именем `compile_provider_gap_brief`; обоих
нормативных имён в workspace нет. Поиск по книге даёт ноль, и следующий
исполнитель не найдёт уже написанного — механизм, которым прошлая кампания
делала «правильные» реализации недостижимыми.

`docs/conformance.toml` для этого не годится: это строгая биекция 58 якорей
`A16.1` ↔ Appendix H, генератор падает при любом другом числе рядов, а `owner`
берётся из колонки Appendix H и в 55 случаях из 58 равен `UNKNOWN`. Символьного
реестра в проекте нет.

Предпочтительное исполнение — переименовать в нормативные имена: имя из книги
становится искомым, стоимость нулевая. Если функциональная форма выбрана
сознательно — запись `Recoverable Deviation` по `A0.6` с owner, причиной,
scope, условием пересмотра и rollback. Выбор за Sol; молчание не считается
выбором.

Общий случай — связывание всех нормативных имён с кодом — в это задание не
входит и решается отдельным WorkItem после закрытия W0.
