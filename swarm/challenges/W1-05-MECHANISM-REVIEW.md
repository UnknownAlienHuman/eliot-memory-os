# W1-05 Mechanism Review — runtime/process contour census

Status: `FOURTH_ATTEMPT_AUTHORIZED_IN_PROGRESS`

Authorization: exactly one mechanism-changed attempt authorized by
`swarm/decisions/W1-RESULT-ENVELOPE-PROGRAM-REVISION-v1.3.md`; evidence remains
`EVIDENCE_ONLY`, with no cutover or terminal update.

## Trigger

Two W1-05 submissions were independently rejected:

1. the first was a small hard-coded contour sample and could omit discoverable
   workspace seams;
2. the second scanned every Git-tracked Rust file, but its process grammar
   recognized only literal `Command::new("...eliot...")` launches while
   claiming an exhaustive runtime/process census. It also omitted current
   non-ignored untracked Rust files.

Rule R11 therefore forbids another incremental regex patch under the old
hypothesis.

## Rejected hypothesis

Scanning executable-name literals and a small IPC symbol list across
`git ls-files -- *.rs` yields the exact runtime contour graph.

This is false. Dynamic/qualified command construction, process wrappers,
Windows process APIs, and named-pipe wrappers can establish a process/IPC seam
without containing a literal target on the same line. Static syntax can expose
the launch site while the target remains unknown; it cannot manufacture a
resolved runtime edge.

## Revised mechanism

The third attempt must:

1. scan the deterministic union of Git cached and non-ignored untracked Rust
   files, so the pre-commit and post-commit source set converges;
2. enumerate every occurrence of a declared process/IPC grammar by reading
   those files directly rather than relying on tracked-only `git grep`;
3. include dynamic and qualified `Command::new`, `StdCommand::new`,
   `ProcessCommand::new`, Tokio command construction,
   `SuspendedJobChild::spawn_named`, Windows `CreateProcess*`, process-executor
   wrappers, and named-pipe client/server/transport operations;
4. resolve a target only from exact local evidence; otherwise emit an explicit
   `UNKNOWN_PROCESS_TARGET` or `UNKNOWN_IPC_TARGET` row;
5. describe completeness as "complete current file-set census for the declared
   grammar", never as a complete semantic/runtime call graph;
6. independently verify the entire W1-05 result envelope, including current
   revision and generator/verifier/inventory hashes;
7. carry regression fixtures for the concrete launch sites found by the second
   gate and for a non-ignored untracked Rust file.

## Decision ceiling

This evidence can support only a recoverable donor/cutover choice whose
rollback preserves both contours. It cannot support retirement option C or a
claim of runtime parity. Runtime target resolution and Product Pulse remain
later execution evidence.

## Acceptance

The third attempt is accepted only when generator self-test/check, independent
verifier self-test/normal, result-envelope tamper tests, and an independent
Luna gate all pass, and each concrete missed launch site is present in the new
inventory with either a resolved target or explicit `UNKNOWN` target.

## Independent third-attempt verdict

The static census mechanism itself passed independent review: 4,034 rows over
546 cached plus nonignored-untracked Rust files; all previously missed
process/IPC sites are present; unresolved targets remain explicit `UNKNOWN`;
there are zero overclaim rows; Cargo A-to-B/B-to-A has zero present direct
edges; and `commit_canonical` remains one definition with zero callers.

The third attempt is nevertheless rejected because its acceptance mechanism
is not post-commit stable and does not verify the full result envelope:

- changes to `observed_worktree_state` and the declared contour sets are
  accepted by the normal verifier;
- generated bytes embed current `HEAD`, so the commit containing them makes
  them stale immediately;
- regression fixtures require the two bootstrap files to remain specifically
  `nonignored_untracked`, which becomes false when the files are committed even
  though the source union is unchanged.
