# Eliot V3 — реестр анализа

**Статус на 2026-10-23 · проверенная база Memory OS `2ab45985`; старые I9.1/I9.3/T12; controller `38db378c` Task→Attempt→binding→dispatch; Hy-Memory `6b0bd866` direct LLM route · активный рабочий реестр, не runtime gate.**

Этот файл отвечает только на четыре вопроса:

1. что именно проверено;
2. на каком основании;
3. какое решение принято или какой разрыв найден;
4. что проверять следующим.

[Architecture](ARCHITECTURE.md), [Implementation](IMPLEMENTATION.md) и [Cognition](COGNITION.md) — нормативный проект. [AUDIT.md](AUDIT.md) — доказательная база и итоговый разбор. [AUDIT-MAP.md](AUDIT-MAP.md) — стабильная матрица исходных требований, исторических аудитов и доноров. **Этот файл — единственный активный реестр дальнейшего анализа.**

## 1. Статусы и правила

| Статус | Значение |
|---|---|
| `CHECKED` | Указанный source/design scope прочитан и вывод согласован с ним. Не означает работающий runtime. |
| `DECIDED` | Для V3 выбрано конкретное решение; реализация ещё не проверена. |
| `PARTIAL` | Прочитан связанный путь или часть донора, но остаётся существенный непроверенный edge. |
| `GAP` | В проекте или выбранном пути интеграции отсутствует необходимая связь; строка называет конкретного владельца разрыва. |
| `OPEN` | Решение описано, но требуется source/API/schema/implementation проверка. |
| `BLOCKED` | Нужный источник недоступен. |
| `NOT SELECTED` | Механизм не нужен выбранной конструкции; это не заявление о полном аудите его исходников. |

Правила ведения:

- строка называет точный объект проверки, а не тему вообще;
- search hit, README или наличие типа не дают статус `CHECKED` для runtime-пути;
- исправление документа переводит `GAP` в `DECIDED`, а не в `IMPLEMENTED`;
- `IMPLEMENTED` появится только после реального кода и наблюдаемого producer→operation→result→consumer;
- новые проценты готовности не вычисляются;
- подробные старые координаты остаются в Git/AUDIT, а не копируются сюда;
- один проход обновляет существующую строку либо добавляет новую материальную строку, а не новый отчёт.

**Собственный дефект V3:** мы правильно удалили separate Dreamer daemon, но затем молча сделали software-development controller обязательным executor первого урока. Получился тот же второй job lifecycle под другим названием. Выбранная замена — один реально заменяемый I/O boundary, поэтому здесь оправдан небольшой trait/client, но не новый process/service/framework:

```text
Memory job + exact recipe/source revisions
→ saved TextRequest(request_key, profile, prompt, output/time limits)
→ one configured TextInferenceClient call outside Store transaction
→ retained TextResult(status, exact body, model/finish/usage/native id when supplied)
→ existing decoder → publish_revision → next context
```

Application job остаётся единственным owner retry/application state. Adapter не принимает Memory IDs как authority, не создаёт Task/Attempt, не управляет workspaces/tools/review и не пишет Memory. Первый implementation — direct OpenAI-compatible adapter с explicit endpoint/model settings. Другой provider или controller adapter реализует ту же narrow boundary позже; provider-specific поля остаются внутри adapter/result metadata. Exact response сохраняется до parse/publication. `complete`, `partial`, transport/provider failure и ambiguous outcome различаются. Timeout не является доказанным non-admission и не разрешает купить второй call с новым ID.

**Проектные контрпримеры, не прогоны:** direct request timeout after provider accepted it; response body returned but Store mutation conflicts; valid no-change; malformed JSON; provider finish reason indicates truncation; switched model route after job claim; controller synthetic Task outlives Memory job; shared persistent session leaks prior episode; disabled learning while remote call finishes. Новый путь сохраняет frozen request/result identity и Base availability без второго task manager.

R-047 — `DECIDED`. R-024 остаётся `PARTIAL`, пока нормативные документы не синхронизированы. R-027/R-046 остаются `GAP` только для optional controller adapter. Код, provider, controller runtime, SQL и product tests не запускались; нет measured quality/cost и independent review. Полный архив и отсутствующий work-system report по-прежнему не получены.

## 4. Решения, которые не открываются заново без нового основания

- не переносить V1/V2 runtime и compatibility facades;
- не создавать второй task manager, swarm, research engine or semantic database;
- не создавать proof/approval/policy platform для обычной памяти;
- не блокировать capture/read из-за embeddings, Dreamer, graph, map or telemetry;
- не использовать similarity как authority, truth or condition proof;
- не считать fixture, shape-valid object, receipt or stored ID выполненной функцией;
- не создавать отдельный SkillRegistry/OutcomeStore/TruthRegistry;
- не требовать experiment/promotion before every provisional useful method;
- не превращать auxiliary deletion history в запрет owner restore;
- не строить универсальный plugin/query/workflow framework до второго реального consumer;
- не менять production behavior для удовлетворения ложного test expectation;
- не объявлять audit/source coverage полнее фактически прочитанного;
- не создавать controller Task/Attempt или persistent agent session для одного Memory text inference.
