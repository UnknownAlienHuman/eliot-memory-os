## T4 — Bind provider turn identity to the exact AgentAttempt (#361 / A-01)

### 1. Decision

**Source baseline:** `b71d74c0b776f2ac63dde670477969657bb30ebd`; all `@b71d74c0` references below refer to this commit, not moving `main`.

A-01's **field/schema owner is `eliot-agent-api`**, while `eliot-agent-coordinator` owns binding lifecycle and reconciliation of externally admitted attempts; neither acquires Governor admission, Kernel process/lease authority, or task Finish (`crates/agent/eliot-agent-api/AGENTS.md:29-40@b71d74c0`; `crates/agent/eliot-agent-coordinator/src/core.rs:100-135@b71d74c0`; owner decision **C361** below).

The execution binding is **exactly one provider execution unit per AgentAttempt**, specifically one exact Codex turn, not its thread; this cardinality is the existing owner decision C361, not a new inference from the more general durable-attempt rule (`docs/architecture/I10-15-agent-execution-fabric-and-durable-swarm.md:19@b71d74c0`; C361).

Reuse `eliot-agent-contracts::AgentAttemptId` and `eliot-contracts::{WorkLeaseId, SessionId, StateFence, ResourceGeneration}` without textual promotion or another wrapper; an incoming execution binding must agree with the externally admitted attempt, its exact lease and authority envelope, its complete fence, and its authenticated runtime generation (`crates/agent/eliot-agent-api/src/lib.rs:10-21@b71d74c0`; `crates/agent/eliot-agent-api/src/lib.rs:72-83@b71d74c0`; `crates/foundation/eliot-contracts/src/lib.rs:185-205@b71d74c0`).

A new turn, including one started after native resume or fork, requires a new admitted AgentAttempt with continuity lineage, whereas steering or reconnecting to the **same recorded turn** retains its binding; session continuity does not establish attempt continuity or authorize lease reuse (`docs/architecture/I07-15-route-continuation-and-transfer.md:3-23@b71d74c0`, `docs/architecture/I07-15-route-continuation-and-transfer.md:39-54@b71d74c0`; C361).

Thread/session observations cannot carry attempt-result, attempt-usage or completion authority, and absent, foreign or ambiguous turn identity cannot be repaired by selecting the active attempt for that thread (`docs/architecture/I07-23-raw-and-normalized-host-events.md:3-18@b71d74c0`; `crates/agent/eliot-agent-api/AGENTS.md:81-97@b71d74c0`; C361).

Route selection remains a candidate, logical admission remains an externally issued decision, and physical observation remains evidence: consolidate the six #369 rows without discarding a divergent or unobserved actual route or inventing `observed = requested` (`crates/agent/eliot-agent-api/AGENTS.md:137-162@b71d74c0`, `crates/agent/eliot-agent-api/AGENTS.md:180-190@b71d74c0`).

Provider results remain candidate-only; neither a provider terminal event, descendant `Completed`, parent finish eligibility, nor an unknown-outcome timeout can establish Task `VERIFIED_COMPLETE` or release unresolved effect ownership (`docs/architecture/I07-09-strict-finish-input-and-outcomes.md:3-30@b71d74c0`, `docs/architecture/I07-09-strict-finish-input-and-outcomes.md:46-58@b71d74c0`; `docs/architecture/I14-20-canonical-runtime-lifecycle-vocabulary.md:26-37@b71d74c0`).

Implement the existing binding decision before the accepted #369 → #370 → #371 migration chain, using small real implementations and minimal discriminating tests, not a second scheduler/journal, fabricated verifier, or test-only completion claim (`START.md:7-25@b71d74c0`; `docs/architecture/A10-04-delegation.md:18-24@b71d74c0`; `docs/architecture/I10-15-agent-execution-fabric-and-durable-swarm.md:3@b71d74c0`).

### 5. Slice plan

#### 5.1 Exact A-01 binding and acceptance rule

The following are **proposed interface spellings inside the existing A-01 owner**, not newly invented owners, runtime ports or already-landed APIs. S1 records their wire revision and explicit old-wire rejection. Names may be adjusted only by the owning contract wave with all consumers changed together; cardinality and authority boundaries do not change.

`eliot_agent_api::ProviderExecutionBinding` binds this immutable tuple:

| Field | Required meaning |
|---|---|
| `attempt_id: AgentAttemptId` | Exact externally admitted ELIOT execution attempt. |
| `lease_id: WorkLeaseId` | Exact canonical owner-issued work lease, copied as its typed value; never reconstructed from a provider/process/thread/UUID spelling. |
| `state_fence: StateFence` | Complete admitted fence, including applicable task/policy/integration dependencies. Shape validation and `is_compatible_with` alone are insufficient. |
| `runtime_generation: ResourceGeneration` | Authenticated generation of the bound provider-runtime resource. Do not numerically cast a P-03 generation or assume every resource generation in the system identifies this runtime. |
| `route: RouteFingerprint` | Exact admitted/requested route identity; later *observed* route is a separate field/receipt and may diverge. |
| `session_id: Option<SessionId>` | Existing ELIOT session attachment, if one was admitted; a native thread ID cannot create this value. |
| `provider_scope_ref` | Opaque, authenticated provider/account/runtime scope reference already established by the admitted route; no credential bytes and no catalogue-as-admission shortcut. |
| `native_session` | Closed `Native { locator }` or `Sessionless` projection. Codex is `Native { thread_id }`; “missing required thread” is not `Sessionless`. |
| `execution_unit` | Namespace plus exact opaque provider execution-unit ID; for Codex this is the exact turn ID, not item ID or request correlation ID. |
| `start_request_id: RequestId`, `start_request_sha256` | Durable ELIOT start-operation correlation and exact admitted request commitment; provider wire request IDs are translated at the adapter boundary, not treated as ELIOT issuance. |

Provider locator and reference strings receive typed, versioned validation and aggregate bounds from the admitted adapter/schema profile; do not invent a universal provider-ID size from one vendor's examples. Provider-native IDs remain opaque and case-sensitive. The binding is stored on the existing admitted attempt projection and lineaged through existing coordination/canonical persistence, not in a new session-to-attempt authority registry. These field requirements derive from `crates/agent/eliot-agent-api/AGENTS.md:47-87@b71d74c0`, `docs/architecture/I10-15-agent-execution-fabric-and-durable-swarm.md:19@b71d74c0`, `docs/architecture/I07-23-raw-and-normalized-host-events.md:3-18@b71d74c0`, and C361; the precise Rust spellings above are the implementation proposal.

**Binding procedure:** persist the admitted start intent/correlation before dispatch; accept a native execution-unit identity only from its authenticated, exactly correlated start response or an already-recorded same-unit reconciliation; then commit the immutable binding through the existing owner path before attributing execution events. A `turn/started` notification racing ahead of the correlated response is retained within bounded raw-event handling, not assigned to whichever attempt is active. Missing correlation times out into an explicit unresolved disposition, not a guessed turn ID. Kernel activation still requires the matching canonical admission receipt (`docs/architecture/I10-15-agent-execution-fabric-and-durable-swarm.md:243-272@b71d74c0`; `docs/architecture/I14-20-canonical-runtime-lifecycle-vocabulary.md:98-100@b71d74c0`).

For attributable execution data require:

```text
binding.attempt_id == admitted.id == coordinator_record.attempt_id
binding.lease_id == admitted.lease == admitted.authority.lease == coordinator_record.lease_id
binding.state_fence == the complete externally accepted fence
binding runtime scope/generation == authenticated runtime observation
native scope/session/execution unit == the immutable recorded binding
```

Checking the last line does **not** require the observed physical route to equal the requested route: a correctly attributed physical observation may report drift. Preserve that drift separately and deny it additional authority. A foreign-turn event is quarantined as an event; it does not itself gain permission to cancel or terminalize a healthy unrelated attempt.

The coordinator enforces one immutable binding per attempt and prevents reuse of the same physical unit for another attempt within the same authenticated provider scope/generation. Exact replay returns the existing binding; changed same-identity content conflicts. No normative text here requires one fresh WorkLease ID for every subsequent attempt: **the owner must admit the lease for the new attempt**; neither automatic lease reuse nor local lease minting is authorized.

`ProviderObservationLineage` has disjoint `SessionObservation` and `ExecutionUnitObservation` cases. Only the latter carries a validated binding. Approval/tool/item observations may inherit turn identity only from an exact recorded request/item-parent chain; a thread match or ambient AttemptId is insufficient. Unknown methods and ambiguous parents preserve bounded raw/redacted evidence without upgrading lineage. Same-turn steer is unchanged; new-turn resume/fork, rehydration or route replacement obtains a new attempt and the existing handoff lineage, separately from delegation parentage (`docs/architecture/I07-15-route-continuation-and-transfer.md:3-54@b71d74c0`; `docs/architecture/I07-23-raw-and-normalized-host-events.md:3-18@b71d74c0`; C361).

### 6. Risks

**Session versus attempt.** `NativeResume` preserving a native **session** in I7.15 does not require every later native **turn** to reuse one ELIOT attempt, so it is compatible with C361. Likewise, an execution can have an unknown outcome while its effects still require nonterminal supervision/reconciliation; these are different lifecycle axes, not contradictory global meanings of “terminal” (`docs/architecture/I07-15-route-continuation-and-transfer.md:3-13@b71d74c0`; `docs/architecture/I14-20-canonical-runtime-lifecycle-vocabulary.md:26-37@b71d74c0`, `docs/architecture/I14-20-canonical-runtime-lifecycle-vocabulary.md:139-149@b71d74c0`).

**Decision versus implementation.** C361 predates the pinned source, but is an issue comment rather than a commit-pinned contract declaration. S1 must retain its exact reference and encode that decision in the existing owner; do not reopen cardinality from the task's stale premise. If a root verifier allows only file citations, the missing statement is specifically the committed `A01_PROVIDER_EXECUTION_BINDING_V1` cardinality/resume/steer declaration—not an unspecified new owner decision.

**Unproven authority edge.** The pinned coordinator exposes a sealed `PLAN_GAP` path, not an accepted production verifier (`crates/agent/eliot-agent-coordinator/src/core.rs:27-77@b71d74c0`, `crates/agent/eliot-agent-coordinator/src/core.rs:125-165@b71d74c0`). S1's reverse-consumer/source review must reveal where authenticated start/admission and runtime-generation evidence actually enter. When the production edge is absent, T1/T5 must provide the existing owners' composition; T4 must not create a caller-set `verified` boolean, public always-successful verifier or fake provider. Schema/validation work can proceed without calling this live closure.

**No invented scope-to-generation conversion.** The docs require exact runtime/fence binding but do not authorize conversion between arbitrary resource, P-03 process, native-worker and provider generations, nor define a universal provider-ID bound. S1 must identify the exact existing resource receipt and admitted schema-profile limits; absent that evidence blocks only the affected adapter's material binding. T2 owns the process contract; T5 owns claim-bound native execution and adapter admission. A numeric cast, session name, successful login or current catalogue row is not an authority bridge.

**Durability and privacy.** An in-memory coordinator map/event vector is not a second canonical journal and cannot make provider launch, cursor acknowledgement or post-crash replay durable by itself. T1/T3 supply the existing governed transition/store edges; T4 supplies their exact identity payload, without choosing new store operations. Retain redacted evidence when raw retention is prohibited; do not persist secrets or hidden reasoning to satisfy an absolute “keep raw” interpretation (`docs/architecture/I07-23-raw-and-normalized-host-events.md:14-18@b71d74c0`).

**Drift and overlapping work.** The cited baseline stays fixed even while managers update `main`; S1 must revalidate direct consumers and every later slice refreezes its exclusive source scope before mutation. A-01 v4 and the already-landed WorkLease/candidate changes must not be reverted. Never silently make #369 depend on the final #370 result schema or #371 payload family: that would create a cycle in the mandated chain.

Binding/route/result/event closure removes their shared-contract obstacles but does not deliver their runtime implementations.
