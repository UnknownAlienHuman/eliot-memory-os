## T13 — Legacy core retirement: U1–U4 и безопасное завершение #1189

### 1. Decision

1. Закрывать четыре legacy-агрегата следует через существующие Governor/Store/Instrument/MCP-контракты, а не переносом монолита или объявлением нового владельца: в текущем каталоге активны только четыре служебных чтения, поэтому новые потребительские пути нужно сначала действительно реализовать (`crates/storage/eliot-store-api/src/operation_catalogue.rs:1-35@7a2b5fd4`).
2. **OWNER DEFAULT (proposed):** сохранить возможности current-state, поиска handles и точного L2, но не старые DTO; использовать `GetCurrentEpistemicPosition`, `GetEvidencePack`, `GetUnderstandingProjectionInputs` с закрытыми схемами ниже, поскольку текущий `ReadApi` уже разделяет state/query/resource, а каталог запрещает generic-upsert/status подмены (`crates/governor/eliot-read/src/lib.rs:436-459@7a2b5fd4`; `docs/architecture/I05-17-semantic-command-families-and-activation.md:17-35@7a2b5fd4`).
3. **OWNER DEFAULT (proposed):** старые `compile_packet_l3`, агрегат `GraphHealthService::health` и неявный `lifecycle_audit` убрать из нового публичного маршрута; смысловое расширение выполнять явными current queries, а не обещать побитовую или семантическую совместимость старого пакета с новым packet-контрактом (`crates/eliot-types/src/memory.rs:949-982@7a2b5fd4`; `crates/eliot-types/src/memory.rs:1102-1235@7a2b5fd4`; `crates/surfaces/eliot-mcp/src/contract.rs:68-101@7a2b5fd4`).
4. **OWNER DEFAULT (proposed):** исторические verification records сохранять как read-only архив с исходными bytes/IDs/lineage, но не превращать в текущие PASS/Allow: legacy допускает Skipped в Passed, тогда как текущий `VerificationRun` требует отдельные execution/outcome/coverage/fence/clock поля (`crates/instrument/eliot-verifier/src/lib.rs:286-349@7a2b5fd4`; `crates/instrument/eliot-instrument-api/src/lib.rs:465-552@7a2b5fd4`; `docs/architecture/I19-06-data-migration.md:3-15@7a2b5fd4`).
5. **OWNER DEFAULT (proposed):** для текущих Rust-проверок использовать существующую зарегистрированную цепочку nextest → diagnostic normalizer → verifier, но считать live evaluator-binding незавершённым до S2: сам registry прямо отделяет записанные identities от live dispatch proof (`crates/instrument/eliot-instrument-runner/src/registry.rs:1-16@7a2b5fd4`; `crates/instrument/eliot-instrument-runner/src/registry.rs:729-780@7a2b5fd4`).
6. Внешний потребитель именно старого serialized `RuntimeStatusReport` не установлен; **OWNER DEFAULT (proposed)** — удалить старый формат без compatibility decoder, проверив установленные клиенты перед переключением, поскольку найденный live-canary импортирует другой, Meta-owned тип (`workspace/tools/eliot-live-canary/src/lib.rs:11-22@7a2b5fd4`; `crates/meta/eliot-runtime-status/src/lib.rs:99-117@7a2b5fd4`).
7. Единственный допустимый cutover — проверенный логический перенос в отдельную Store generation, сравнение без второго владельца, затем один canonical cutover receipt; после no-return восстановление означает forward repair, а не оживление старого writer (`docs/architecture/I19-06-data-migration.md:3-15@7a2b5fd4`; `docs/architecture/I19-16-object-level-migration-disposition-and-authority-cutover.md:3-17@7a2b5fd4`).
8. По прямому ограничению задания `%LOCALAPPDATA%\Eliot` и его данные **никогда не удаляются этой работой**: S2–S7 готовят новый путь, S8 меняет установленный маршрут только после доказанного переноса, S9 удаляет исходный код legacy, но не данные владельца; это усиливает, а не отменяет требование сохранить old DB read-only (`docs/architecture/I19-06-data-migration.md:10-12@7a2b5fd4`; `workstreams/T7.md:192-240@7a2b5fd4`).

Полный `CurrentEpistemicPosition` не заменяется локальным `PositionState` или строкой status: исходный contract уже различает admitted view/candidate и связывает позицию с внешним receipt (`crates/smart/eliot-epistemic-contracts/src/admitted.rs:1-6@7a2b5fd4`; `crates/smart/eliot-epistemic-contracts/src/admitted.rs:76-108@7a2b5fd4`). Store переносит его owner-validated wire payload/schema binding; это не требует назначения Store владельцем epistemic algebra.

Структурные типы новых wrappers: `handle`, `kind`, `preview`, `payload_ref`, cursor и элементы `*_refs` — bounded strings; `record_revision:u64`; `relations/edges` — массивы объектов со string kind/from/to. `freshness={source_heads:[RevisionHead], stale:bool}` описывает наблюдённые source revisions, не verification freshness; `coverage={requested:u32, returned:u32, truncated:bool}` описывает только размер этого bounded read, не полноту доказательства. `disposition` в E — закрытая метка `canonical | candidate | historical`, не epistemic verdict. Все новые wrappers запрещают unknown fields; ограничения nonblank/URI/exact IDs проверяются существующими owner codecs.

Общие defaults: `limit=64`, максимум 256 items/page; совокупный input ≤64 KiB, result ≤3 MiB; oversized payload возвращается через exact resource/blob reference, а не режется незаметно. Cursor связывает operation, selectors digest, scope, fence, dependency heads и last key; смена любого binding требует нового query. При exact URI несовместимый cursor/handle отвергается. Значения лимитов — **OWNER DEFAULT (proposed)** внутри текущих catalogue ceilings, не утверждение о существующей реализации (`crates/storage/eliot-store-api/src/operation_catalogue.rs:100-119@7a2b5fd4`).

Ответ: `{export_id, section, records:[EcxfRecord], next_cursor?, page_sha256}` под тем же fence; blobs идут отдельно через Blob API. Все три consumer reads плюс export должны иметь настоящий adapter handler, generated manifest и один working consumer до рекламы. Lifecycle historical UI, новый graph-health aggregate и универсальный audit browser не активируются этой задачей. **Identity/consistency/error правила.**

- Ledger key — `(source store identity, legacy project ID, record family, legacy record ID)`; target scope выдаётся нынешним владельцем. Совпавшие UUID или dirname не доказывают тождество. Task/scope/concept refs переводятся тем же явным способом; unknown/ref outside authorized scope → typed rejection, не default project. Старые числовые revisions не присваиваются новой generation.
- Legacy minimum revision удовлетворяется только записанным migration receipt → target dependency heads. Нет mapping — typed `MIGRATION_MAPPING_INCOMPLETE`, агент обновляет handles/query. `AtLeastRevision` без minimum не превращается в Latest. Stable reads используют A/read/B; timeout/churn не превращается в Published. Preview может быть stale только с явной stale/coverage отметкой, не как подтверждение актуальной позиции (`docs/architecture/I05-20-read-model-consistency-and-cache.md:14-35@7a2b5fd4`).
- Сохраняются различия invalid input, forbidden, missing, stale, churn, unsupported, cancelled/deadline и unknown write outcome. Нынешний `ReadError::Store(String)` реально стирает тип при `From<StoreError>`; S4 добавляет `ReadError::StoreFailure(eliot_store_api::StoreFailure)` вместо разбора текста, не новый независимый taxonomy (`crates/governor/eliot-read/src/lib.rs:363-433@7a2b5fd4`).
- Caller-supplied provenance handles — declared lineage, не доказательство authenticity или новой verification. Архивный handle всегда отмечает исторический источник; status/proof не повышается при read или migration (`crates/governor/eliot-read/src/lib.rs:145-165@7a2b5fd4`; `docs/architecture/I19-06-data-migration.md:15@7a2b5fd4`).

#### U2. Verification: архив и текущий evaluator

**Архивировать, не выбрасывать.** Сохранить исходную запись и доступные raw files/blobs с digest, original IDs, old profile/plan/command/result/time полями и ссылкой на disposition ledger. Архив читается только как historical evidence; его наличие не удовлетворяет текущий finish gate. Не синтезировать прежние scope, StateFence, invocation, coverage или clock из текущей установки. Отсутствующие поля остаются отсутствующими в historical envelope. Если соответствие record family известно, импортировать допустимую candidate/history projection и exact source reference; иначе disposition `ARCHIVED`, без фальшивого current `VerificationRun` (`docs/architecture/I19-06-data-migration.md:3-15@7a2b5fd4`; `docs/architecture/I19-16-object-level-migration-disposition-and-authority-cutover.md:5-17@7a2b5fd4`).

All-skipped, пустой запуск, недостающие required tests, truncated/malformed output или отсутствие raw lineage не становятся PASS. Полный failed run — FAIL, неполное покрытие — PARTIAL/UNKNOWN по текущему контракту, а не Allow (`crates/instrument/eliot-instrument-nextest/src/lib.rs:74-113@7a2b5fd4`; `crates/instrument/eliot-instrument-api/src/lib.rs:465-552@7a2b5fd4`).

`VerificationRun::validate()` необходим, но недостаточен: он не доказывает сам по себе истинность присланного coverage или наличие каждого raw artifact. Результат принимает существующий Governor finish owner; evaluator не выдаёт себе finish authority. Исторические non-Rust/custom profiles не переименовывать в nextest: архивировать, а новые их runs направлять только в реально зарегистрированный подходящий provider, иначе typed unsupported.

Перед S8 controller проверяет scripts/client configs и реальную runtime traffic. Найденный старый reader либо обновляется вместе с клиентом, либо остаётся явным blocker его переключения; добавление decoder «на всякий случай» не допускается. | Обязательная запись census | Источник / decision rule |
|---|---|
| Все binary/build identities, PID+creation time+parent, services/tasks, bridge/provider processes | Exact executable path и SHA-256, launch/config identity, owner current/legacy/unknown. Process name сам по себе не разрешает adoption или termination. Unknown live holder блокирует activation. |

| Pending/unknown effects, write IDs/idempotency keys, old receipts, external actions, leases/attempts | Для каждой незавершённой операции запросить настоящий outcome у её владельца. Реальное чтение source blobs и completed target blob receipts обязательно (`crates/storage/eliot-ecxf/src/lib.rs:179-227@7a2b5fd4`; `crates/storage/eliot-ecxf/src/lib.rs:295-323@7a2b5fd4`).
   - **Не выдумывать fence:** legacy export без current StateFence остаётся явно legacy source archive, не притворяется готовым ECXF/1 canonical snapshot. Current target admission выдаёт **новой** imported candidate/history state её настоящий fence; затем current Store делает проверяемый ECXF/1 export/readback. Этот fence не переносится задним числом в старые verification records. Не подделывать ExportFence.consistent, sequence range или blob-ready receipts (`crates/storage/eliot-ecxf/src/lib.rs:96-176@7a2b5fd4`).
   - Purge ledger сохраняется и применяется при target import/read: сохранённый source archive не разрешает воскресить purged/revoked content; live leases, sessions и authority не импортируются (`crates/storage/eliot-ecxf/src/lib.rs:459-469@7a2b5fd4`; `crates/storage/eliot-backup/src/lib.rs:8-10@7a2b5fd4`).
   - **Тест:** малый реальный round-trip с raw JSON необычного formatting, relation endpoints, legacy verifier и blob; повторный import того же archive/chunk id+digest не дублирует objects; unknown commit сначала разрешается через `ResolveWriteReceipt`, а не blind retry. Несовпавший digest/недостающий blob блокирует affected scope. Streaming/page limits проверяются без загрузки 120 GB в один `Vec`; сравнение всех object IDs/digests/counts/relations полное, interactive MCP выборка небольшая.
   - **Deferred:** live multi-writer replication и compression tuning. **Unblocks:** безопасный перенос owner data; не разрешает пока переключать writer.

9. **T7-S8b — Один cutover receipt и реальные клиенты. Owning issue: #1189; activation/installed owner #11.**

   - **Acceptance sequence:** (1) legacy работает до готовности candidate; (2) кратко остановить новые writes через owner-controlled maintenance и дождаться/reconcile in-flight; (3) final coherent export или доказанный bounded delta, повторный full denominator check; (4) candidate readback, isolated test-scope remember/recall и все используемые клиенты; (5) один receipt выбирает новую generation, старый write route отключён; (6) clients reconnect, новый owner remember/read/restart proof проходит. UI calls во время drain получают maintenance/retry, не мнимый успех. Нулевой downtime не обещается.
   - **До no-return:** при ошибке candidate отключается, legacy остаётся владельцем; нельзя потерять уже принятые legacy writes. **После no-return:** только forward repair, никаких автоматических dual-writes/fallback на старую DB. `%LOCALAPPDATA%\Eliot` остаётся read-only сохранённым источником, без expiry-driven delete.

### 6. Risks

- **Drift main относительно pin.** Этот документ не утверждает, что сегодняшние handlers отсутствуют: он фиксирует `7a2b5fd4`. Перед каждым slice сравнить его paths с current main и переиспользовать landed решения. Не подменять pin citations новой реализацией.
- **Registry entry ≠ работающий verifier.** S2 первым проверяет actual invocation/profile/parser/output/consumer. Отсутствующий Testd binding или невозможный output format выявляется одним реальным запуском до крупных удалений; это implementation prerequisite, не оправдание canned proof.
- **120 GB и byte preservation.** ECXF APIs содержат `Vec` и canonical `Value`; использовать их на bounded pages/records, не на всей установке. Нет достаточного места или недоступен исходный blob — не переключать affected scope и ничего не удалять.
- **Legacy semantics не восстановимы из IDs.** Неизвестные verifier/fence/clock/ordering поля не угадываются. Raw source остаётся доступным, current candidate/history сохраняет ограничения, а новый verified result требует новой проверки.
- **Скрытые клиенты/незавершённые effects.** Source grep и наличие процесса не дают полного installed census. S5 связывает конфиги, live attach, authoritative receipts и owner-confirmed clients; S8 повторяет проверку после drain.
- **Переусложнение.** Одна машина, один owner, один verified transfer и один cutover receipt; не добавлять tenant IDs, custom auth, распределённый coordinator, второй registry или rollback service. Владелец/контракт остаются прежними; предлагаемые defaults ограничивают объём работы.

Статус этого документа: source-grounded решение и implementation plan. Rust, PowerShell census, реальный Store export/import, installed MCP и cutover в этой сессии **не выполнялись**. Публикация `T13.md` не означает закрытие #1189 или успешную миграцию данных.
