### 1. Decision

Keep the provider-neutral public contract in **`crates/kernel/eliot-process`**, the sole high-level Windows implementation in **`crates/instrument/eliot-process-executor`**, and audited OS primitives in **`crates/kernel/eliot-platform-windows`**; these are existing, explicitly named boundaries, not a reason to create `eliot-process-windows` or another executor crate (`docs/architecture/I10-08-12-source-ownership-and-first-crate-extraction-wave.md:27-44@b71d74c0`; `config/architecture-boundaries.toml:72-80@b71d74c0`).

Consumer cores depend on the public contract, while composition roots select the Windows implementation; retain the existing data-only `eliot-instrument-api` dependency, but introduce no InstrumentRunner, provider, Governor, or legacy-facade runtime dependency into Host/Kernel (`docs/architecture/I02-23-capability-family-topology-and-crate-extraction-decisions.md:3-15@b71d74c0`; `crates/kernel/AGENTS.md:29-43@b71d74c0`; `crates/instrument/eliot-instrument-api/src/lib.rs:1-6@b71d74c0`).

“One executor” means one semantic implementation and facade, **not one global process owner**: Kernel, testd, User Broker and admitted supervisors keep their documented trees, admission and recovery responsibilities (`docs/architecture/I10-08-02-ip0-one-windows-processexecutor.md:3@b71d74c0`).

Retain `start`, `inspect`, `cancel` and `reconcile`; Kernel alone supplies and freshly validates dispatch authority immediately before resume, and consumers send inert admission requests rather than serializing an executable permit across a process boundary (`docs/architecture/I10-08-02-ip0-one-windows-processexecutor.md:20-38@b71d74c0`; `crates/kernel/eliot-process/src/lib.rs:588-603@b71d74c0`).

Complete the binding through existing intent, permit, owner, manifest, State Fence and execution-evidence records, without inventing a second installation, principal, lease, canonical-state or recovery owner (`docs/architecture/I04-05-generation-vector-and-state-fence.md:3-17@b71d74c0`; `crates/kernel/AGENTS.md:35-43@b71d74c0`; `crates/kernel/AGENTS.md:54-68@b71d74c0`).

The public wire must have one active revision incorporating the canonical lineage-aware epoch from #64; the proposed next process-contract revision is **`eliot-process-contract-v4`**, not a second execution API, and old scalar-epoch records must not be silently promoted into active authority (`workstreams/core-daemons/AGENTS.md:129-138@b71d74c0`; `crates/foundation/eliot-contracts/src/epoch_identity.rs:1-235@b71d74c0`; `crates/kernel/eliot-process/src/lib.rs:38-41@b71d74c0`).

Drain, retry, provider choice, repair recipes and semantic completion remain outside the executor: cancellation is not rollback, raw process observations are not verification, and an unknown effect requires reconciliation rather than another launch (`docs/architecture/I14-13-idle-drain-and-cancellation.md:1-5@b71d74c0`; `docs/architecture/I14-25-doctor-implementation-contract.md:1-17@b71d74c0`; `crates/kernel/AGENTS.md:66-68@b71d74c0`).

After the shared boundary is implemented, migrate **native worker first, Doctor second**, as requested by T2; each preserves its existing owner and needs a real process edge rather than a replacement mock or a new local execution policy (`START.md:18-21@b71d74c0`; `docs/architecture/I10-08-12-source-ownership-and-first-crate-extraction-wave.md:46-71@b71d74c0`).

#### Concrete reuse and defects

**P-03.** `ProcessIntent` already binds operation/tree/Job/image/session IDs, generation, executable hash, argv, cwd, environment projection and resource limits into its effect digest. `ProcessExecutionAdmissionRequest` is inert. `ProcessRequest` is consuming, non-Clone and non-Deserialize. `PermitIssuance` already has exact dependency revision heads. Stable `ProcessOwnerBinding` is separated from ephemeral `ProcessSessionBinding`. Reuse these distinctions; do not invent a second request/receipt family for each consumer (`crates/kernel/eliot-process/src/lib.rs:385-830@b71d74c0`). Its `FencingToken` nevertheless still contains a scalar epoch, while the foundation already contains `EpochId`; this is an implementation gap, not permission to truncate lineage (`crates/kernel/eliot-process/src/lib.rs:161-218@b71d74c0`; `crates/foundation/eliot-contracts/src/epoch_identity.rs:1-235@b71d74c0`).

**P-04 / native mismatch.** `WorkerCore::demand_start` rejects an empty observing sink immediately after a successful `start`, before readiness inspection. The Windows implementation registers the running process and returns a start receipt, but its evidence sink publication is in `reconcile`. The actual pairing therefore has a start-proof gap. Implement one real initial observation after successful resume/registration; keep the worker's binding checks and observation-only proof ceiling. Publishing this observation is a proposed compatibility repair, not a claim that the normative text dictates a particular callback schedule (`crates/modules/eliot-native-worker-core/src/lib.rs:212-392@b71d74c0`; `crates/instrument/eliot-process-executor/src/lib.rs:455-775@b71d74c0`).

**Streams.** `ProcessEvidence::new` accepts old raw-reference strings and converts them to the legacy stream representation through `new_typed`. Its outer evidence schema is still v2: the defect is legacy/quarantined stream content, **not** an assertion that the executor emits a v1 outer envelope. Installed execution must emit actual typed stream metadata and retained raw-evidence handles through the existing stream-sink contract (`crates/kernel/eliot-process/src/execution_evidence.rs:153-207@b71d74c0`; `crates/instrument/eliot-process-executor/src/lib.rs:729-775@b71d74c0`).

**Kernel.** `bins/eliot-kernel/src/process_execution.rs` already contains ORS-backed evidence/replay and stable-owner binding machinery. Reuse it for reservations, durable unknown outcomes and reconnect; do not substitute the executor's in-memory operation map for durable idempotency, and do not introduce another journal (`bins/eliot-kernel/src/process_execution.rs:1-450@b71d74c0`).

**Native.** `NativeWorker<E,A,R,C>` and `WorkerCore` already accept governing ports; preserve that composition. The executable is not proved operational merely because these types exist. A consumer-process boundary carries authenticated inert requests and observations, never shared Rust references or a deserialized `ProcessRequest` (`bins/eliot-native-worker/src/lib.rs:1-132@b71d74c0`; `crates/kernel/eliot-process/src/lib.rs:588-603@b71d74c0`).

Execution records intent before one consuming dispatch; post-intent uncertainty is keyed to the same effect rather than blindly retried.
