## Remaining defect (A4 / W11), reproduced from source at b7e9e334

`required_by` decides which omitting disposition may close a given omission from the
quarantined child's own `GrantRecoveryRecord.status` and nothing else:

```rust
match record.status {
    GrantStatus::PendingActivation => Self::NeverAdmitted,
    GrantStatus::Active | GrantStatus::Revoked => Self::RevokedAndFenced,
}
```

`GrantRecoveryRecord.status` is a verbatim copy of the durable `CapabilityGrant.status`
(`grants.rs:757`, and `grants.rs:734` on the way back in), and **no production path ever
advances it to `Active`**. Verified: `git grep -n "status\s*[:=]\s*GrantStatus::" origin/main -- crates`
returns exactly seven non-test hits, every one of them inside a test module —
`grants.rs:3919` (`cfg(test)` opens at 3863), `authority_revocation.rs:998` and `:1017`
(`889`), `owner_closure_provider.rs:2532` (`2444`), `governor_closure_source.rs:1433`
(`mod tests` opens at 1359), `grant_activation_port.rs:7114` and `:7214` (`7031`),
`composition.rs:14258` (`11640`).

Production activation only flips in-memory presentation state.
`activate_grant` (`composition.rs:10043`) retains the presentation and calls
`note_activated` (`composition.rs:10061`); `note_activated`
(`authority_recovery.rs:1046`) assigns `self.state` and nothing else. The single
receipt-over-status projection, `AuthorityPresentation::grant_status`
(`authority_recovery.rs:1130`) reached through `authority_grant_status`
(`composition.rs:10658`), is consumed only by `require_activatable_grant`
(`composition.rs:10730`) and by test assertions (`composition.rs:14329`–`14649`).

So `required_by` can only ever return `NeverAdmitted`. `admit_resolved`'s `NeverAdmitted`
arm (`quarantine_evidence.rs:816`) then needs only `enforcement.is_none()` plus
`!child_admitted` (`quarantine_evidence.rs:825`, via `grant_is_admitted`). A child that was
activated in an earlier epoch, then fenced out of the admitted map and quarantined, closes
its omission as `NeverAdmitted` / `InertWithExactProof` with **zero enforcement receipt** —
exactly the A4/W11 failure.

## MAKE

1. Add a durable-boundary-only activation-readback carrier to the evidence chain, shaped
   like the existing `retained_quarantine_enforcements` map — owner-supplied, never
   defaulted, never caller-presented, absence fails closed.
   In `owner_closure_provider.rs`, add the field beside `retained_quarantine_enforcements`
   (`owner_closure_provider.rs:116`) and accept it through
   `restore_with_retained_quarantine_decisions` (`owner_closure_provider.rs:425`).
   In `governor_closure_source.rs`, add the matching section on `GovernorClosureRestore`
   (`governor_closure_source.rs:86`) / `GovernorClosureRestoreWire`
   (`governor_closure_source.rs:179`), bump `GOVERNOR_CLOSURE_RESTORE_VERSION`
   (`governor_closure_source.rs:175`) 3 -> 4, and document it in the same lineage voice the
   v2 and v3 notes use (`governor_closure_source.rs:151-174`). No `serde(default)`, no
   `skip_serializing_if`.
   In `owner_closure_feed.rs`, thread it through
   `synchronize_owner_feed_with_quarantine_evidence` (`owner_closure_feed.rs:246`) from the
   production caller in `bins/eliotd/src/owner_feed.rs`.
2. Make the discriminator read that carrier instead of the durable status.
   `required_by` becomes: activation receipt present for the child -> `RevokedAndFenced`
   (exact enforcement evidence required); activation receipt proven absent -> `NeverAdmitted`;
   anything unresolved -> `RevokedAndFenced` or refuse, never `NeverAdmitted` by default.
   The Governor admission (`VerifiedQuarantineBinding::admit`,
   `quarantine_evidence.rs:519`, called from `owner_closure_provider.rs:724`) and the Kernel
   admission (`admit_restored`, `quarantine_evidence.rs:620`, called from
   `governor_closure_source.rs:966`) must derive the same answer from the same carrier.
3. Fix the caller binding in `grants.rs`. `bind_quarantine_omission` locates the child's
   recovery record by id and hands it to `required_by` (`grants.rs:3235`); pass the
   activation readback alongside it, and keep
   `GrantGraph::satisfies_omission` (`grants.rs:3489`) reading only sealed bindings.
4. Source the readback from the owner that already holds it.
   `CommittedAuthorityActivation` (`grant_activation_port.rs:3879`) binds
   `receipt` + `ors_record_id` + `ors_subject_id` + `mechanical_subset_commitment` +
   `grant_graph_revision`, and its own doc is the governing rule verbatim: *a canonical grant
   row without this committed activation is not authority*. Durable readback is
   `eliot_ors::RecoveryStore::load_capability_grant` (`store.rs:3913`, impl `:36068`)
   returning `CapabilityGrantProjection` with phase `Applying|Active|Fenced|Released`.
   `eliot-governor` already depends on `eliot-kernel-core` and `eliot-authority` already
   depends on `eliot-runtime-contracts`, so no new dependency edge appears.
