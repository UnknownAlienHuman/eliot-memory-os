**START:** `eliot_ipc::Session::establish` and `Session::establish_with_server` still hard-code
`session_epoch: 1`, and `Session::fence` only bumps that destructible local object.
`bins/eliot-kernel/src/front_door_driver.rs::serve_connection` fences only the local session on
disconnect, while the existing owner
`bins/eliot-kernel/src/host_request_route.rs::fence_host_requests_for_connection` has only bridge
callers. `bins/eliotd/src/daemon_kernel_client.rs::transact_async_with_identity` opens a fresh
transport per operation while `DaemonKernelClient::connect` keeps one stable `connection_id`, so
`LocalReadAttemptState::is_owned_by` accepts a reconnect as owner of the previous attempt.

**MAKE:** Allocate the transport-session generation in `KernelComposition` at bind time so
`bind_session_inner` supplies a monotonic value that never repeats per `connection_id` in a boot,
removing the hard-coded literal from the production constructors. Wire the daemon
disconnect/EOF/error arms of `serve_connection` to one idempotent Kernel owner call carrying exact
`(connection_id, session_epoch, launch_nonce)` plus the process-binding reference, which removes
claim ownership and closes or advances the fencing generation for every live claim family without
deleting unknown-effect history. Then require a live Kernel-held current connection/session record
— not only the retained tuple — for claim, source read and result submit, and apply that same check
to the campaign-packet, task-controller, observe and finish queues in `daemon_claim_queue.rs`.

**DO NOT:** no new authority token, credential, crypto scheme, global Session store, session
database or project/task resolver; no one-second claim timeout and no expiry inferred from an old
consumed nonce; no change to the eligibility, deadline or byte-charge semantics of
`fence_all_host_requests` / `fence_host_requests_for_connection`; no restructuring of
`daemon_runtime.rs::submit_local_read_result_idempotent`'s retry legs; no Doctor/Testd platform-role
redesign; no widening of `validate_eliotd_peer` / `validate_eliotd_client_binding`. No architecture
section allocates a transport-session generation (`MISSING-CONTRACT
docs/architecture#transport-session-identity`, verified silent) — do not invent one; the nearest
normative rule is I15.18#delegation-gate ("Revocation invalidates new calls before semantic
reconciliation ... An old serialized introduction is not authority after restart/restore").
