**START:** the recovery contour is substantially implemented and **PRESERVE** on
`origin/main@b7e9e334569639a6290baeacf82bf44941def506` — stable operation / idempotency /
canonical-request identity, receipt lookup before any same-identity resend when an open
record exists, exact receipt binding and evidence digest, one same-identity retry only
after a proven rollback, the durable unknown-commit record plus Ordering Scope pause,
the checked ORS observation that fails closed when the owner is unavailable, the typed
Dreamer retained-state handling, and `recover_commit`
(`crates/kernel/eliot-kernel-service/src/commit_recovery.rs:1035`). Five live defects
are confirmed in source.

**D1 — a second ungoverned write path.**
`crates/kernel/eliot-kernel-service/src/store_gateway.rs::BorrowedCanonicalStoreClient::apply_prepared`
(`store_gateway.rs:935`) calls `self.gateway.store.apply_prepared(...)` directly. It
does not reach `KernelStoreGateway::apply`, `recover_commit`, or the checked pause gate.
Its own `require_active_generation` only proves the gateway's generation is still the
active route — not that the mutation went through the durable recovery owner. Real
production UserAutomation paths use it via
`CanonicalUserAutomationStore::new(BorrowedCanonicalStoreClient::new(self))`, so a
possible commit with no `UnknownCommitRecord`, no retained Ordering Scope set, no
pause, no visible Problem State and no restart-resumable disposition.

**D2 — `apply_reserved` releases on post-send failure.**
`crates/kernel/eliot-kernel-service/src/store_gateway.rs::KernelStoreGateway::apply_reserved`
(`:1490`) matches exactly one uncertain variant, `Err(StoreError::MissingReceiptEnvelope)`
(it calls `begin_execute_after_send` then `mark_unknown_outcome` and keeps
`Executing`/`Reconciling`). Every other `Err(error)` falls into the catch-all arm at
`:1600` → `store_gateway.rs::refuse_determinate_reserved_write` (`:10103`) →
`let _ = cancel_before_send(owner, token);` (`:10131`). The EBP transport maps unknown
delivery, receive failure, response decode/correlation failure and typed
unknown-outcome Store failure to `StoreError::UnknownOutcome { operation_id }` and
returns it unchanged, so those all release the ordering position after the send — the
false-noncommit transition I14.21 forbids. Same for a wrong-kind, malformed or
misbound post-send response (`InvalidReceipt`, `IdentityConflict`).

**D3 — `recover_commit` stages nothing before the send.**
`crates/kernel/eliot-kernel-service/src/commit_recovery.rs::recover_commit` (`:1035`)
stages an `UnknownCommitRecord` **lazily**, only after the mutation send and receipt
reconciliation both remain unknown. A fresh key therefore has no durable Kernel
write-attempt record before dispatch; a crash after the Store effect boundary but
before `open_problem_state` leaves ORS with no retained record, and the next
presentation re-enters the fresh-send path instead of receipt-first recovery. The
reserved path already shows the right shape — stage identity/order before send, retain
`Executing`/`Reconciling` after a possible effect, terminalize only from exact evidence.

**D4 — the paused-scope view has no consumer.**
`store_gateway.rs::KernelStoreGateway::paused_ordering_scopes` (`:1450`) and
`commit_recovery.rs::paused_ordering_scope_view` (`:1622`) exist, but
`git grep` finds only their definitions and tests — no Doctor route, Recovery View,
CLI/wire method or authenticated disposition command. A caller-facing error string is
not the Human/Doctor recovery surface I14.21 requires. Related: `store_exchange.rs`
carries the retained-state/terminal-evidence handoff that the pause consumer would read
back through — it is in this write set so the readback can be bounded rather than
invented elsewhere.

**D5 — the pause ledger read is bounded only after materialization.**
`crates/kernel/eliot-ors/src/store.rs::list_open_unknown_commits` (`:6261`) takes no
page or limit and returns `Result<Vec<UnknownCommitRecord>, OrsError>`.
`commit_recovery.rs:555` calls it and only then checks
`records.len() > MAX_OBSERVED_OPEN_COMMITS` (`:564`, the constant is
`MAX_OBSERVED_OPEN_COMMITS = 4096` at `commit_recovery.rs:308`). The whole ledger is
materialized and decoded before the declared ceiling is enforced. Note the honest
reading it already supports: on an over-limit answer the observation is reported
*"incomplete, not empty"* (`:568`).

**MAKE:** route **every** canonical mutation, `BorrowedCanonicalStoreClient` included,
through the one Kernel-owned recovery gateway — the borrowed client may expose reads,
but a second ungoverned `apply_prepared` write path may not remain. Before the first
possible Store effect, durably retain the exact operation id, idempotency key,
canonical request hash, complete Ordering Scope set, `StateFence`, owner/schema version
and write stage; replays must classify that retained intent **before** any send. Use
one post-dispatch classifier for all uncertain outcomes — `MissingReceiptEnvelope`,
`UnknownOutcome`, unknown delivery/receive/decode/correlation and unusable post-send
receipts all stay `Executing`/`Reconciling`; none may call `cancel_before_send` or
release order. Release a pre-send reservation only from owner-issued evidence that the
Store effect was definitely not attempted; a generic `StoreError` is not such evidence
after dispatch. Query the exact receipt first on restart or re-presentation; resolve
committed outcomes in ORS, permit one byte-identical resend only after a proven
rollback, otherwise retain the pause and the original identity. Add a bounded
authenticated Recovery View over open unknown commits with an evidence-verifying
disposition — never a caller-authored terminal outcome. Replace
`list_open_unknown_commits()` with a storage-bounded max-plus-one page plus an explicit
serialized-byte ceiling; over-limit or unreadable state closes mutation admission
while preserving last-known positive pauses.

**DO NOT:** do not create a second recovery system, journal or coordinator — extend
the existing ORS unknown-commit record and the existing Kernel reserved-write owner.
Never `cancel_before_send` after a possible send. Never fabricate a terminal
disposition on an unknown effect, and never blind-resend. Do not weaken the exact
receipt verifier, the same-identity rollback retry, the checked ORS pause observation,
the Dreamer retained-state taxonomy, or the prohibition on `ACCEPTED_PENDING`. Do not
collapse typed failures into strings or shared codes between layers to make the
classifier fit — one issue's own record flags `store_gateway.rs` substring matching in
`dreamer_job_dispatch.rs::dreamer_store_error_fences` as exactly that defect, and
classifying `CommitRecoveryError` by type is a separate issue, not this one. Do not
scope onto the native-worker / process-start replay planes
(`protocol/native_worker_replay.rs`, `protocol/native_worker_claim.rs`) — this is
distinct from them. Do not touch the legacy `control_wal`.
