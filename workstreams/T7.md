### 1. Decision

Закрывать нужно **один граф зависимостей четырёх legacy crates**, но небольшими build-closed изменениями: сначала установить владельца и переключить конкретное ребро, затем удалить старую реализацию; все read/write/recovery edges одного mutable object переключаются вместе, а shadow/dual-read допускается только для сравнения, не как второй действующий владелец (`docs/architecture/I19-16-object-level-migration-disposition-and-authority-cutover.md:17@b71d74c0`).

`eliot-app` не получает новую жизнь в виде переименованного монолита: CLI/MCP остаются поверхностями, semantic application — в Governor, runtime authority — в Host/Kernel, storage execution — в закрытом bridge; временно сохраняется только поведение с доказанным текущим потребителем либо конкретной regression-фикстурой (`crates/eliot-app/AGENTS.md:31-64@b71d74c0`).

`WriterActor`, очереди, admission и recovery нельзя перенести одним объектом: semantic decision строит `eliotd`, Kernel механически проверяет и упорядочивает **тот же** `PreparedTransition`, Store исполняет именованную операцию; T7 потребляет результат T1/#18 и T3/#19, а не создаёт собственный переходный writer (`docs/architecture/I01-08-exact-ownership-and-call-paths.md:3-23@b71d74c0`; `docs/architecture/I05-01-storage-boundary.md:3-26@b71d74c0`).

Оба внешних потребителя `eliot-types` должны уйти с агрегатного контракта, но разными способами: для CLI сохранить ограниченный read-only decoder старой конфигурации, необходимый существующей проверке Store collision; для verifier не копировать старые run/verdict DTO в новый общий crate, а разделить историческую запись и нынешнее доказательство с invocation, fence, freshness и coverage (`bins/eliot/src/main.rs:613-699@b71d74c0`; `bins/AGENTS.md:47-54@b71d74c0`; `crates/instrument/AGENTS.md:44-58@b71d74c0`; `docs/architecture/I19-14-old-object-compatibility-map.md:43@b71d74c0`).

Текущим владельцем `RuntimeStatusReport` остаётся **`eliot-runtime-status` в Meta**, а не `eliot-types` и не новый третий contract crate; legacy report допускается лишь как отдельно опознанный исторический формат без преобразования старого `Healthy` в доказанную готовность новой установки (`crates/meta/AGENTS.md:30-34@b71d74c0`; `crates/meta/AGENTS.md:54-63@b71d74c0`; `crates/meta/eliot-runtime-status/src/lib.rs:99-117@b71d74c0`).

MCP и recall сохраняются как проверяемое пользовательское поведение, а не как старый путь к authority: surface передаёт inert intent, нынешние владельцы устанавливают identity/scope/fence, read возвращает ограниченный результат с revision/provenance; старые DTO и локальные shortcuts не становятся действующим контрактом только потому, что на них есть тест (`crates/surfaces/AGENTS.md:44-59@b71d74c0`; `docs/architecture/I01-08-exact-ownership-and-call-paths.md:25-57@b71d74c0`; `crates/eliot-app/AGENTS.md:46-47@b71d74c0`).

Удаление агрегатов разрешено только после disposition каждого активного объекта, переноса либо удаления его потребителей и фикстур, проверки новой границы и cutover receipt; неизвестная семантика старых данных становится candidate/archive, а после no-return допускается forward repair, но не восстановление прежнего truth owner (`docs/architecture/I19-03-component-disposition.md:23@b71d74c0`; `docs/architecture/I19-06-data-migration.md:3-15@b71d74c0`; `docs/architecture/I19-16-object-level-migration-disposition-and-authority-cutover.md:3-17@b71d74c0`).

#### Различия, которые нельзя потерять

**Read tier задаётся семантикой.** Handle/preview относится к Q0, current task/scope state — Q1, exact evidence/relations — Q2, Active View/Context Packet — Q3; это назначение сохранённого поведения, не автоматическое равенство Rust DTO. Для coherent packet нужен stable-scope double-read тех же revision keys; для exact-fence — точное совпадение всех зависимостей, а не один legacy `MemoryRevision` (`docs/architecture/I05-20-read-model-consistency-and-cache.md:3-31@b71d74c0`).

**Config — защитный consumer.** `observe_legacy_governor_config` и `revalidate_legacy_governor_gate` читают старый TOML, вызывают validation и `reject_store_collision`, проверяют стабильность retained file и отсутствие legacy process. Нужен именно этот acceptance predicate, включая ошибки и default handling, а не просто отсутствие `use eliot_types`. Private decoder не запускает Governor, не использует credentials и не назначает новую конфигурацию. Удаление проверки, принятие malformed input либо безусловный отказ для любого существующего файла не является эквивалентной миграцией (`bins/eliot/src/main.rs:613-699@b71d74c0`).

**Same name ≠ same schema.** Legacy runtime report содержит PID/mode/data root; current report — installation/generation/journal/ORS/readiness/gaps. Legacy verification run содержит plan/profile/command results; current run требует registered verifier, invocation, scope, evidence, fence и clocks. Нельзя заполнить отсутствующие поля `default()`, временем миграции или `Healthy/Pass`. Кроме того, существующий `run_status` допускает `Skipped` в ветку `Passed`, а `verdict` доверяет переданному статусу; сохранение этой логики как current proof — запрещённая migration divergence, не обязанность обратной совместимости (`crates/eliot-types/src/runtime.rs:97-107@b71d74c0`; `crates/meta/eliot-runtime-status/src/lib.rs:99-117@b71d74c0`; `crates/eliot-types/src/verification.rs:141-152@b71d74c0`; `crates/instrument/eliot-instrument-api/src/lib.rs:429-465@b71d74c0`; `crates/instrument/eliot-verifier/src/lib.rs:286-367@b71d74c0`; `crates/instrument/AGENTS.md:49-58@b71d74c0`).

**Первый falsifier — S1, а не финальное удаление Cargo members.** Сопоставление настоящих callers с полным feature/wire/effect ledger может обнаружить больше внешних consumers, а перенос config gate — скрытые defaults/validators.
