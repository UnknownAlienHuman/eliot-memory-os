# ELIOT bootstrap

This bootstrap is mandatory for every nontrivial project task. Before any
filesystem, grep, glob, shell, web, or broad repository tool:

1. Call OpenCode's `skill` tool with `eliot-work` for implementation/resumption,
   `eliot-recover` for failures, and `eliot-finish` before completion.
2. Follow that loaded skill. For material work, make the first ELIOT call
   `eliot_compile_packet_l3` with the exact goal; project/task scope is supplied
   by the bound session and context arrives on the response.
3. Read current truth before recall, expand only exact handles, keep all model
   writes candidate-only, and use the verifier returned by the packet.

If either tool is unavailable, report that integration blocker; do not silently
substitute ordinary file references for Eliot evidence. Record which Eliot evidence
changes the decision. A host name never grants a role. A read-only task needs no
write.
