# ELIOT bootstrap

This bootstrap is mandatory for every nontrivial project task. Before any
filesystem, grep, glob, shell, web, or broad repository tool:

1. Call the connected Eliot MCP tool `eliot_host_session_status`.
2. Call OpenCode's `skill` tool with `eliot-understanding` for analysis or
   `eliot-task-cycle` for implementation/resumption.
3. Follow that loaded skill: resolve project identity, read current truth before
   recall, and expand only exact Eliot handles before broad search.
4. Recover daemon identity only from `eliot_runtime_status` and bounded autonomy
   only from `eliot_autonomy_run_status`. Never substitute an `AgentSession`, role
   status, or verification run for those canonical identities.

If either tool is unavailable, report that integration blocker; do not silently
substitute ordinary file references for Eliot evidence. Record which Eliot evidence
changes the decision. A host name never grants a role. A read-only task needs no
write.
